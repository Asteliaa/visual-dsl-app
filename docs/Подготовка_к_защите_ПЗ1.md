# Практическое занятие 1. Middleware и шаблонизаторы: подготовка к защите

Ветка репозитория: `pz21`. Проект: VisualDSL (диаграммы из DSL-кода), Express + EJS, данные в массиве в памяти.

---

## 1. Описание задания: что и как нужно было сделать

**Цель.** Освоить middleware в Express.js (логирование, авторизация, обработка ошибок) и шаблонизатор EJS для генерации HTML на сервере.

**Задачи (индивидуально, тематика по курсовому проекту):**

1. Создать Express-приложение с EJS (`app.set('view engine', 'ejs')`, `app.set('views', ...)`).
2. Middleware логирования: метод, URL, время запроса. **Вариант (четный): журнал выводится таблицей** (время, событие, метод, URL, статус, длительность, пользователь, IP) на странице `/logs`.
3. Middleware имитации авторизации: нет `?auth=1` - редирект на `/login` (или `req.user = { name: 'Гость' }`).
4. Динамические страницы: главная (список), детальная (по ID), форма добавления; данные передаются из контроллеров.
5. Middleware ошибок: 404 (`404.ejs`) и 500 (`500.ejs` + лог ошибки).
6. Данные - глобальный массив в памяти, БД нет.

**Порядок (по методичке):**

| Часть | Что сделать | Где в проекте |
|-------|-------------|---------------|
| 1 | Установить EJS, настроить view engine | `package.json`, `app.js` |
| 2 | Папка `views/`, общий каркас (layout или partials), 3 страницы `index/item/add` | `views/`, `views/partials/` |
| 3 | Логирующее (с таблицей журнала) и авторизующее middleware | `middlewares/logger.js`, `models/logStore.js`, `views/logs.ejs`, `middlewares/auth.js` |
| 4 | Маршруты `GET /`, `GET /item/:id`, `GET /add`, `POST /add` (редирект на главную) | `routes/pageRoutes.js`, `controllers/pageController.js` |
| 5 | Обработка 404 и 500 | `middlewares/errorHandlers.js`, `views/404.ejs`, `views/500.ejs` |

**Сдача:** отчет PDF (титул, цель, листинги middleware и EJS, скриншоты главной/детальной/формы/404, ответы на 30 вопросов, выводы) + ссылка на GitHub (ветка `pz21`) с инструкцией по запуску (она в `README.md`).

## 2. Технические термины

| Термин | Объяснение |
|--------|------------|
| **Node.js** | среда выполнения JavaScript на сервере |
| **Express** | минималистичный веб-фреймворк для Node.js: маршруты и middleware |
| **npm** | менеджер пакетов; `package.json` - список зависимостей и скриптов |
| **middleware** | функция `(req, res, next)`, которая стоит в цепочке обработки запроса |
| **req / res** | объекты запроса и ответа |
| **next()** | передать управление следующему middleware; `next(err)` - обработчику ошибок |
| **маршрут (route)** | пара «HTTP-метод + путь» и обработчик: `app.get('/', ...)` |
| **Router** | мини-приложение для группы маршрутов (`express.Router()`) |
| **контроллер** | функция-обработчик с логикой маршрута (`controllers/`) |
| **шаблонизатор** | подставляет данные в HTML-шаблон на сервере; здесь - EJS |
| **EJS** | шаблоны с тегами `<% %>` (код), `<%= %>` (вывод с экранированием), `<%- %>` (вывод без экранирования) |
| **partial** | частичный шаблон (шапка, подвал), подключаемый через `include` |
| **view engine / views** | настройки Express: какой шаблонизатор и где лежат шаблоны |
| **SSR** | рендеринг HTML на сервере (в отличие от рендеринга в браузере) |
| **query-параметр** | часть URL после `?`: `/?auth=1` -> `req.query.auth` |
| **path-параметр** | часть пути: `/item/:id` -> `req.params.id` |
| **редирект (302)** | ответ, по которому браузер переходит на другой URL (`res.redirect`) |
| **PRG-паттерн** | POST -> redirect -> GET, чтобы форма не отправлялась повторно при обновлении |
| **коды ответа** | 200 OK, 302 редирект, 400 неверные данные, 404 не найдено, 500 ошибка сервера |
| **res.locals / app.locals** | переменные, доступные во всех шаблонах (на запрос / на все приложение) |
| **статика** | файлы, отдаваемые как есть (CSS, JS, картинки): `express.static` |
| **XSS** | внедрение скрипта через непроверенный ввод; EJS `<%= %>` экранирует HTML |
| **error-handling middleware** | middleware с 4 параметрами `(err, req, res, next)` |
| **REST API / JSON** | интерфейс для программ; ответы в формате JSON (`/api/diagrams`) |
| **Jest / Supertest** | тест-раннер и библиотека HTTP-запросов к приложению без запуска порта |
| **покрытие кода (coverage)** | доля кода, выполненная тестами |
| **Postman** | программа для отправки HTTP-запросов и проверки ответов |
| **ветка Git (`pz21`)** | отдельная линия разработки для этой работы |

## 3. Теория по ПЗ

### 3.1 Что такое middleware и как идет запрос

```
Запрос -> [static] -> [logger] -> [парсеры тела] -> [attachUser] -> [маршруты] -> [404] -> [500] -> Ответ
```

- Функции выполняются **в порядке подключения**.
- Каждая либо отвечает клиенту (`res.send/render/redirect`), либо вызывает `next()`. Если не сделать ни того, ни другого - запрос «зависнет».
- Типы: уровня приложения (`app.use`), уровня маршрутизатора (`router.use`), встроенные (`express.json()`, `express.urlencoded()`, `express.static()`), сторонние, **обработчики ошибок**.
- `app.use(fn)` - для всех методов и путей с префиксом; `app.get(path, fn)` - только GET и точный путь.
- Middleware на один маршрут: `router.get('/add', requireAuth, handler)`.

### 3.2 Порядок важен

| Middleware | Где | Почему |
|------------|-----|--------|
| статика | до маршрутов | CSS не должен проходить логику страниц |
| логгер | в начале | чтобы логировать все запросы |
| `express.urlencoded/json` | до маршрутов | иначе `req.body` пустой |
| `attachUser` | до маршрутов | маршруты используют `req.user` |
| 404 | после всех маршрутов | сработает, только если никто не ответил |
| 500 (4 параметра) | самым последним | ловит ошибки всех предыдущих |

### 3.3 Шаблонизатор EJS

- Подключение: `npm i ejs`, `app.set('view engine','ejs')`, `app.set('views', path)`.
- Рендер: `res.render('index', { items })` - `index.ejs` из `views/`, данные доступны как переменные.
- Теги: `<% код %>`, `<%= значение %>` (экранирует `<` `>` `&` - защита от XSS), `<%- значение %>` (без экранирования, только для доверенного HTML и `include`).
- Циклы и условия - обычный JS внутри `<% %>`.
- Общий каркас: `<%- include('partials/header') %>` и `footer` (альтернатива - `express-ejs-layouts` с `<%- body %>`).
- `res.render` формирует HTML из шаблона, `res.send` отправляет готовое значение как есть.

### 3.4 Имитация авторизации

Настоящей авторизации нет (это тема ЛР3): `?auth=1` считается «вошедшим». Чтобы не терять признак при переходах, в ссылки добавляется суффикс `authQuery` (`?auth=1`). Гость: `req.user = { name: 'Гость' }`, защищенные маршруты (`/add`) перенаправляют на `/login`.

### 3.5 Обработка ошибок

- 404: обычный middleware без ошибки в конце цепочки.
- 500: `(err, req, res, next)`; ошибки синхронного кода попадают сюда автоматически, из асинхронного - через `next(err)` (в Express 4) или автоматически (Express 5).
- Логировать ошибку (`console.error`) и показывать пользователю безопасную страницу без стека.
- Запросы к `/api/*` получают JSON, а не HTML.

### 3.6 Форма и PRG

`GET /add` показывает форму -> `POST /add` валидирует поля на сервере -> при ошибке снова рендерит форму (код 400, введенные значения сохраняются) -> при успехе добавляет элемент в массив и делает `redirect('/')`.

## 4. Что и где происходит в коде

### Структура

```
server.js                    запуск порта
app.js                       сборка приложения: EJS, статика, middleware, маршруты, обработчики ошибок
middlewares/logger.js        лог: метод, URL, статус, время (мс) -> консоль + журнал logStore
middlewares/auth.js          attachUser (req.user, authQuery) и requireAuth (редирект на /login)
middlewares/errorHandlers.js notFoundHandler (404) и serverErrorHandler (500)
routes/pageRoutes.js         маршруты HTML-страниц
routes/diagramRoutes.js      маршруты REST API
controllers/pageController.js контроллеры страниц (render/redirect)
controllers/diagramController.js контроллеры API (JSON)
models/diagramStore.js       массив diagrams в памяти + create/update/remove/reset
models/logStore.js           журнал запросов в памяти (до 500 записей) для таблицы /logs
seeds/diagrams.js, seeds/logs.js  начальные и демонстрационные данные (seed)
extras/                      заготовки на случай правок на защите (см. extras/README.md)
scripts/demo.js              демо-сценарий: наполняет массив и журнал запросами всех видов
views/*.ejs, views/partials/ шаблоны (logs.ejs - таблица журнала)
public/css/style.css         стили (URL /static/css/style.css)
__tests__/                   тесты Jest + Supertest
scripts/screenshots.js       автоскриншоты для отчета
```

### Путь запроса `GET /item/1?auth=1`

1. `server.js` -> `app.js` принимает запрос.
2. `logger` запоминает время, `attachUser` ставит `req.user = Администратор` и `res.locals.authQuery = '?auth=1'`.
3. `pageRoutes` -> `GET /item/:id` -> `pageController.item`.
4. Контроллер ищет элемент в `models/diagramStore.js`; нет - `render('404')`, есть - `render('item', { item })`.
5. `views/item.ejs` подключает `partials/header` и `footer`, выводит поля через `<%= %>`.
6. После ответа сработает `finish` -> `logger` печатает строку в консоль.

### Путь `POST /add?auth=1`

`urlencoded` заполняет `req.body` -> `requireAuth` пропускает -> `pageController.addSubmit` проверяет `title`, `dsl`, `type` -> ошибки: `render('add')` с кодом 400; успех: `store.create`, `redirect('/?auth=1')`.

### Что именно требует задание и где это

| Требование | Файл |
|------------|------|
| EJS, view engine | `app.js` строки `app.set('view engine'...)`, `app.set('views'...)` |
| логирование метода, URL, времени | `middlewares/logger.js` |
| проверка `?auth=1` / редирект на `/login` / `req.user` Гость | `middlewares/auth.js` |
| 3 страницы + передача данных | `views/index.ejs`, `item.ejs`, `add.ejs` + `pageController.js` |
| 404 / 500 с логом | `middlewares/errorHandlers.js`, `views/404.ejs`, `500.ejs` |
| данные в массиве | `models/diagramStore.js` |

## 5. Как запускать (терминал и Postman)

### 5.1 Терминал (PowerShell или Git Bash)

```bash
cd D:\VisualDSL-Platform
git checkout pz21
npm install

```

Откройте в браузере: http://localhost:5000

| Что открыть | Что должно быть |
|-------------|-----------------|
| `http://localhost:5000/` | список диаграмм, пользователь «Гость» |
| `http://localhost:5000/?auth=1` | то же, пользователь «Администратор» |
| `http://localhost:5000/item/1?auth=1` | детальная страница |
| `http://localhost:5000/add` | редирект на `/login` |
| `http://localhost:5000/add?auth=1` | форма добавления |
| `http://localhost:5000/abc` | страница 404 |
| `http://localhost:5000/debug/error` | страница 500 |
| `http://localhost:5000/logs?auth=1` | **таблица журнала**: время, событие, метод, URL, статус, мс, пользователь, IP; фильтры по методу и событию |

Смотрите окно терминала - там строки лога вида `GET /item/1?auth=1 -> 200 (3.04 мс)`.

Другие команды:

```bash
npm test                 # все тесты (117)
npm run demo             # (при запущенном сервере, в другом терминале) наполняет данные и журнал
npm run test:coverage    # покрытие
npm run dev              # запуск с автоперезапуском (nodemon)
```

Порт можно сменить: `$env:PORT=3001; npm start` (PowerShell).

### 5.2 Postman

1. Запустите сервер (`npm start`).
2. В Postman: **Import** -> выберите `docs/postman/VisualDSL-PZ1.postman_collection.json`. Переменная `baseUrl` = `http://localhost:5000`.
3. Выполняйте запросы коллекции по порядку (кнопка **Send**):

| Запрос | Метод и URL | Ожидаемый ответ |
|--------|-------------|-----------------|
| список | `GET /api/diagrams` | 200, JSON-массив |
| поиск | `GET /api/diagrams?search=jwt` | 200, 1 элемент |
| по id | `GET /api/diagrams/1` | 200 |
| создание | `POST /api/diagrams`, Body -> raw -> JSON `{"title":"...","dsl":"..."}` | 201 и объект с `id` |
| валидация | `POST` без `title` | 400 |
| обновление | `PUT /api/diagrams/1`, JSON с `title` и `dsl` | 200 |
| удаление | `DELETE /api/diagrams/2` | 204 без тела |
| несуществующий | `GET /api/diagrams/999` | 404 JSON |
| журнал | `GET /logs?auth=1` | 200, HTML-таблица (в Preview видна таблица) |
| HTML | `GET /?auth=1` | 200, в Body - HTML (вкладка Preview покажет страницу) |
| защита | `GET /add` (в Settings отключите *Automatically follow redirects*) | 302, заголовок `Location: /login` |
| форма | `POST /add?auth=1`, Body -> **x-www-form-urlencoded**: `title`, `type`, `dsl` | 302 на `/?auth=1` |
| 404 / 500 | `GET /no-such-page`, `GET /debug/error` | 404 / 500 HTML |

Для POST через форму тело должно быть именно `x-www-form-urlencoded` (его разбирает `express.urlencoded`), для API - `raw JSON` (разбирает `express.json`).

Покажите `middlewares/logger.js` (запись в `logStore`) и `views/logs.ejs`.

10. **Порядок middleware.** Покажите `app.js` сверху вниз: статика -> логгер -> парсеры -> `attachUser` -> маршруты -> 404 -> 500, объясните, почему именно так.
11. **Тесты.** `npm run test:coverage` - 117 тестов, покрытие строк 100 %. Seed-данные для тестов лежат в `seeds/` (`diagrams.js`, `logs.js`), тесты - в `__tests__/` и `extras/__tests__/`.
12. **Postman (по желанию).** Запрос `POST /api/diagrams`, затем `GET /?auth=1` - диаграмма видна и на странице (общий массив).
13. **Отчет.** Покажите PDF и ответьте на вопросы из раздела 4 отчета.

**Типичные вопросы преподавателя и краткие ответы:**

- *Что будет без `next()`?* Запрос зависнет.
- *Почему `urlencoded` до маршрутов?* Иначе `req.body` будет `undefined`.
- *Чем `<%=` отличается от `<%-`?* Первый экранирует HTML (безопасно), второй нет (риск XSS).
- *Как Express понял, что это обработчик ошибок?* По четырем параметрам.
- *Почему 404-middleware последний?* Он срабатывает, только если ни один маршрут не ответил.
- *Где хранятся данные?* В массиве `models/diagramStore.js`; после перезапуска сервера возвращаются к начальным.

**Если что-то не работает:**

| Проблема | Решение |
|----------|---------|
| `Cannot find module 'ejs'` | `npm install` |
| порт занят (`EADDRINUSE`) | `$env:PORT=3001; npm start` |
| `/add` всегда редирект на `/login` | в URL нужен `?auth=1` |
| форма из Postman не добавляет | Body должен быть `x-www-form-urlencoded` |
| `npm run screenshots` не запускается | нужен установленный Google Chrome |
| `npm run demo` пишет, что сервер не отвечает | сначала `npm start` в другом терминале |
